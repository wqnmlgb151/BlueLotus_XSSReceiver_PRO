# v4.2.0 — 记录完整性与兼容性修复

日期：2026-10-30。

## 主要变化

- 可选唯一 ID：秒级时间加 128 位随机后缀，时间字段保持不变；兼容旧 ID 读取、查询、删除、统计、通知和 CSV。
- 同目录临时文件完成后原子发布，创建冲突返回失败；读取不再回写归属地。
- 嵌套参数递归处理与深度限制、中文搜索、项目筛选及操作后统计刷新。
- 修复 AES 全局查找表作用域与 PHP 8.2 数值转换，保持旧密文格式。
- API 严格校验 CSRF Token，jQuery、jQWidgets 和下载请求均配套；无效参数类型返回 400。
- 保活按协议/主机/端口校验相对跳转，缺少 cURL 返回 503。
- 增加测试、JS 构建、依赖和性能清单、恢复文档及发布自检。

## 升级要求

1. 暂停业务写入并成套备份真实配置、记录、JS 和描述；先在隔离副本验证恢复。
2. 先部署双格式读取兼容版本，保持实际 `UNIQUE_RECORD_ID_ENABLE` 关闭；验证目标文件系统支持硬链接和原子重命名后再考虑启用。
3. API 必须带登录会话和 `X-CSRF-Token`，仅 Referer 的旧客户端会返回 403。后端和三个前端运行产物必须一起更新。
4. 保活非默认端口白名单改用 `host:port`；确认 PHP cURL 已启用。
5. 启用新 ID 后不要回退到只识别十位 ID 的旧版本。AES 环境需保留已修复的完整版本。

## 验证与限制

本地 PHP 8.2.29 Windows NTS 离线回归通过，涵盖未加密/RC4/AES、旧 AES 密文样本、100 条同秒并发记录和失败路径；隔离 HTTP 与浏览器验证涵盖登录、项目搜索、导出、删除和受控回环保活。

1 万条小型合成记录的全量列表约 5.6 秒，不保证大规模实时查询；详见性能文档。未改变历史加密算法，也未升级第三方组件。本次是源码发布，不是生产部署；Linux/真实磁盘、磁盘满与崩溃、真实备份恢复及 RPO/RTO 由部署环境验收。
