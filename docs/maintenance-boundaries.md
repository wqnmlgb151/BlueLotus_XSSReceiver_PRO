## 性能结论

原始输出见 `performance-baseline.json`，脚本 `tests/benchmark.php`。使用临时目录、RC4、小型合成记录及已有 location 字段，每个操作单次测量，不是生产 P95 或压力测试。

| 条数 | 列表 | 搜索 | 统计 | JSON 导出 | 最大峰值内存 |
|---|---|---|---|---|---|
| 1000 | 525 ms | 336 ms | 316 ms | 365 ms | 4 MiB |
| 10000 | 5618 ms | 4098 ms | 3635 ms | 3472 ms | 22 MiB |

全量扫描随规模增长，万条时可能超过前端初始 2 秒超时。真实字段、磁盘缓存和杀毒扫描会改变结果。测量已完成；没有约定容量与延迟预算，不引入索引、缓存或数据库。实际需要稳定管理万条以上时，应先约定分页与导出语义及目标预算，再实施并比较；仅延长超时不能当作性能优化。

## Web 验证复现

1. PowerShell 7 执行 `tests/prepare-web.ps1 -FixtureRoot <尚不存在的隔离绝对目录>`，生成合成配置和应用副本。
2. 启动站点：`php -d extension=curl -d session.save_path=<隔离目录>/sessions -S 127.0.0.1:8791 -t <隔离目录>`。
3. 启动合成目标：`php -S 127.0.0.1:8792 <隔离目录>/target.php`。8793 不启用目标。
4. 执行 `node tests/web.mjs http://127.0.0.1:8791 <隔离目录>/target.log`，使用全新夹具；脚本断言日志严格为 `/dir/start`、`/dir/next` 成对事件，Cookie 是 `fixture=only`，无 `/blocked`。
5. 浏览器登录合成账号，密码 `fixture-pass`；检查项目切换、中文搜索、CSV 下载和行删除。结束后关闭浏览器及两个进程。
